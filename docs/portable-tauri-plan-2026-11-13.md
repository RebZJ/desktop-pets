# Portable Tauri plan — 13 November 2026

Historical implementation/research record. For the current three-feature portable architecture and its verified limits, see [portable validation](portable-native-validation-2026-11-14.md).
Keep the Tauri 2 / React / Rust application and SQLite. Move working capabilities out of the Swift worker in small vertical slices. Do not replace the framework or change speech models just to achieve portability. A Rust Tauri module can use portable libraries; making every module a separately published plugin would add packaging work without helping this application.

This is a source review and migration recommendation, not evidence that Windows or Linux builds currently work. No accounts, calendars, microphones or permission prompts were accessed; no models or runtimes were installed.

## The smallest useful change now

1. Let dictation capture audio even when Accessibility or target-field capture is unavailable. Preserve automatic insertion on the existing supported Mac path, but make a recoverable transcript the baseline result.
2. Use the official `tauri-plugin-clipboard-manager` for an explicit **Copy transcript** action. It supports the three desktop platforms and has Rust and JavaScript APIs. This does not make automatic paste portable. Keep the official global-shortcut plugin already installed for dictation and Quick Hide. [Clipboard](https://v2.tauri.app/plugin/clipboard/), [global shortcuts](https://v2.tauri.app/plugin/global-shortcut/).
3. Start recording before model loading. Preserve audio and show a useful error if inference fails. Keep custom words in the ASR request, rather than requiring a large language model to rewrite every utterance.

Owners: `src-tauri/src/dictation.rs` currently gates global dictation on `permissions.status` / Accessibility before `audio.start`; `src-tauri/src/lib.rs::stop_dictation` owns transcription and audio recovery; `src-tauri/Cargo.toml`, initialization in `lib.rs`, `src/api.ts`, and the transcript UI in `src/Pace.tsx` own clipboard integration. Reuse existing cancellation epochs, recording locks and transcript events. If the JS plugin API is exposed, grant only its needed clipboard-write permission; a Rust-owned command avoids exposing extra plugin commands.

The next capture slice should maintain the current `audio.start` / `audio.stop` result shape, with microphone PCM captured in Rust and Moonshine warming concurrently. It needs a real device smoke test before replacing the working Mac capture path.

## What exists and what fits

| Capability | Verified upstream option | Decision and limits |
| --- | --- | --- |
| Microphone and whole-system audio | [CPAL 0.18.2](https://github.com/RustAudio/cpal/tree/v0.18.2), Apache-2.0. Released 16 August 2026. Windows WASAPI, macOS CoreAudio, Linux ALSA plus optional PulseAudio/PipeWire. | Prefer an app-owned Rust audio module. CPAL already includes Windows loopback and Mac process-tap loopback; its documented Mac loopback floor is 14.6. Linux needs the selected audio backend and build libraries. Its callbacks provide samples; buffering, resampling, persistence and error propagation remain our responsibility. |
| Higher-level capture candidate | [clipclip 0.2.7](https://github.com/sincekmori/clipclip), MIT OR Apache-2.0; published 5 November 2026, repository active 13 November. Wraps CPAL, ringbuf and rubato. `start(Config, callback)` returns a recording handle; `Source::Separate` gives independent mic/system segments with track/timestamps. | Worth a bounded spike before writing our own capture plumbing. WAV-only configuration avoids its default Opus native dependency. It is a small, young crate, not a vetted Tauri plugin. Test startup failure, tail flush, device changes, cancellation and long capture. Its README's `0.1` install example and Mac floor lag the current manifest/CPAL docs. |
| Existing Tauri mic plugin | [tauri-plugin-mic-recorder](https://github.com/ayangweb/tauri-plugin-mic-recorder), MIT, Tauri 2, Windows/macOS/Linux; last pushed 11 June 2025. | Do not adopt unchanged. Its API is start/stop-to-WAV, not a live PCM pipeline. [Source](https://github.com/ayangweb/tauri-plugin-mic-recorder/blob/master/src/commands.rs) marks recording active before fallible setup, discards callback write errors, and manually declares the CPAL stream Send/Sync. Fixing it would mean owning a fork. |
| Per-app system audio | Current ScreenCaptureKit path; CPAL's [Mac loopback implementation](https://github.com/RustAudio/cpal/blob/v0.18.2/src/host/coreaudio/macos/loopback.rs) captures the output mix. | Do not silently turn an app-only recording into whole-system capture. Retain the existing adapter until a selected-app backend has equivalent behavior. Whole-system capture no longer requires bespoke Swift on all three desktop OSes, but selected-app capture still needs platform-specific implementation/testing. |
| Tiny dictation | [Moonshine](https://github.com/moonshine-ai/moonshine), portable C API with Windows/macOS/Linux support; active 10 November 2026. | Keep the current streaming models and C runtime. `MoonshineASR.swift` already wraps `moonshine_load_transcriber_from_files`, stream functions and `moonshine_transcriber_set_keyterms`; move that ownership into Rust. There is no official Rust binding listed upstream, so keep the FFI boundary small. Current selected en/zh/ja/es models are streaming variants: upstream says these are MIT, unlike legacy non-English non-streaming models. [Model terms](https://github.com/moonshine-ai/moonshine/blob/main/docs/models/available-models.md). |
| Whisper fallback / meeting transcription | [whisper.cpp](https://github.com/ggml-org/whisper.cpp), MIT, current Windows/macOS/Linux runtime; active 13 November. | Already used as CLI from Swift. Invoke the same pinned CLI from Rust and preserve VAD, timestamps, output validation, cancellation and failure audio. No inference rewrite is required. |
| Speaker diarization | [NVIDIA NeMo-Speech.cpp v0.3.0](https://github.com/NVIDIA/NeMo-Speech.cpp/releases/tag/v0.3.0), Apache-2.0 runtime; release includes CPU Windows x64, Linux x64/arm64 and macOS x64/arm64 builds. | Existing `nemo-speech diarize` can move from Swift process launch into Rust. The current installer unnecessarily restricts it to Mac arm64. The [Nemotron model card](https://huggingface.co/nvidia/Nemotron-3-Diarization) separately declares OpenMDW-1.1. Preserve model notices and checksums. Do not equate a speaker number with a known person's identity. |
| Local chat / notes / live help | [llama.cpp](https://github.com/ggml-org/llama.cpp), MIT, actively maintained, CPU and hardware backends across desktop platforms. | Appropriate portable successor to the MLX-only chat backend, later. Keep `chat.generate` and cancellation contract. Existing MLX safetensors are not GGUF; select and validate the exact supported model artifact instead of calling the current download portable. No need to change the UI or notes database. |
| Kiki / KittenTTS Micro 0.8 | [KittenTTS](https://github.com/KittenML/KittenTTS) and [Micro 0.8 model](https://huggingface.co/KittenML/kitten-tts-micro-0.8), Apache-2.0; official 0.8 ONNX implementation remains available. | ONNX makes this portable in principle, but current MLX weights/voice conversion are not an interchangeable runtime. Defer this migration behind dictation and meetings. Do not claim sherpa-onnx is a drop-in for this exact model: its [0.8 support issue](https://github.com/k2-fsa/sherpa-onnx/issues/3196) is still open. |

The official [sherpa-onnx Tauri microphone application](https://k2-fsa.github.io/sherpa/onnx/tauri/vad-asr-mic.html) is a useful maintained reference: CPAL capture, VAD, ASR, playback and exports with Mac universal, Windows x64 and Linux x64/arm64 builds. Sherpa itself is Apache-2.0 and actively maintained. Its broad model catalog does not justify changing the current successful Moonshine/Whisper choices or assuming every model variant is supported.

## Upcoming meetings and one meeting workspace

Use one meeting record/session for transcript, speaker labels, notes and live help. Capture mic and remote tracks separately, retain original timeline offsets, and send one session's transcript into notes/live-help requests. Build the **Take notes?** prompt around a calendar event ID plus occurrence start time, so repeated syncs, wake/resume and calendar edits do not create duplicate sessions. Declining or hiding a prompt must not start recording.

No general, maintained desktop-calendar Tauri plugin was verified that removes provider/account work. [Anarlog's calendar plugin](https://github.com/fastrepl/anarlog/tree/main/plugins/calendar) is active and MIT, but depends on its own workspace crates and API client; its shared [calendar module](https://github.com/fastrepl/anarlog/blob/main/crates/calendar/src/lib.rs) offers Apple only on macOS and Google/Outlook through its connection backend. It is a reference, not a small standalone dependency.

For real cross-platform upcoming events, use read-only provider integrations: [Google events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list) with a bounded time range and expanded recurring instances; [Microsoft calendarView](https://learn.microsoft.com/en-us/graph/api/calendar-list-calendarview?view=graph-rest-1.0) for occurrences and exceptions. Connect only when the user opts in. Native Apple Calendar can remain an optional macOS adapter. An imported calendar file can be an explicit offline source, but should not be advertised as automatic account synchronization.

Keep scheduling/deduplication in Rust and reuse the existing companion window for the prompt. The official [notification plugin](https://v2.tauri.app/plugin/notification/) can supply optional system notifications; it does not discover calendars. Meeting-app process presence is a weak secondary signal, not proof a call started. [OpenWhispr](https://github.com/OpenWhispr/openwhispr), MIT and active 12 November, confirms the practical split: provider calendar caches/reminder scheduling, plus separate [OS audio-activity detectors](https://github.com/OpenWhispr/openwhispr/blob/main/src/helpers/audioActivityDetector.js) and [process detectors](https://github.com/OpenWhispr/openwhispr/blob/main/src/helpers/meetingProcessDetector.js). It still ships native platform helpers despite using Electron. Borrow the sequencing, not its framework.

Owners: `src/MeetingCloud.tsx`, meeting operations and events in `src-tauri/src/lib.rs`, `src-tauri/src/notes.rs`, `src-tauri/src/db.rs`, and a narrowly scoped future calendar module. Capture extraction reaches `native/PaceNative/Sources/PaceNative/Meetings.swift`; runtime extraction reaches `Transcription.swift`, `Diarization.swift`, `Inference.swift`, `Models.swift`, their existing tests and `native/scripts/`. Keep fixtures/testing seams in `src/api.ts` and `tests/e2e/meeting-cloud.spec.ts` aligned.

## Capture privacy and Quick Hide

Use Tauri's existing `contentProtected` / `set_content_protected` first and the existing global-shortcut-driven hide path. Preserve `pet_panel.rs` only for the macOS non-activating pet behavior and current public AppKit acknowledgement; replacing that code is not a prerequisite for portable speech.

- Windows: the underlying [SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity) supports exclusion from Windows 10 version 2004, but is not a universal security guarantee.
- macOS: a successful sharing-property setter does not prove ScreenCaptureKit exclusion. The [Tauri upstream issue](https://github.com/tauri-apps/tauri/issues/14200) remains open; [Apple's forum response](https://developer.apple.com/forums/thread/808016) also documents capture behavior requiring investigation. Do not promise Cluely-style invisibility across recording applications.
- Linux: do not claim general capture exclusion. Quick Hide is the portable user-facing fallback, with shortcut support tested on the intended X11/Wayland desktop rather than assumed from a generic Linux label.

Owners: `src-tauri/src/lib.rs::apply_capture_protection_on_main`, `src-tauri/src/pet_panel.rs`, `src-tauri/src/companion.rs`, settings in `src/api.ts`, and all Tauri window definitions. Hiding must invalidate pending UI work so a completed request cannot reopen a private panel.

## Order and proof before claiming support

1. Dictation recovery and official clipboard plugin; preserve the current Mac pipeline.
2. One Rust microphone + Moonshine slice, then the already portable Whisper and NeMo processes. Use recorded fixtures for malformed PCM, sample-rate conversion, vocabulary and transcript timing; test real start/stop/device loss separately.
3. Shared meeting workspace and prompt scheduler. Connect one real calendar provider only when its account flow is in scope.
4. Whole-system Rust capture on each OS, then explicit per-app support. Keep source semantics visible.
5. Portable LLM and TTS after the two main flows work. Add platform build/bundle config and runtime checksums alongside each migrated capability; current `tauri.conf.json` only targets `app`/`dmg`, and current native build scripts are Mac-specific.

Skipped: a framework rewrite, a general plugin framework, new model downloads, account connections, and new OS permission prompts. Cross-platform runtime availability is verified upstream; actual Pace builds, capture latency, permission behavior and capture exclusion on Windows/Linux remain untested.
